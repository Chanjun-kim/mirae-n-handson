# RCA 리포트 마스킹 규칙

`docs/rca/` 에 저장하는 리포트의 본문 · 표 · 원문 발췌 · 명령 예시 전체에 적용한다. 원본 로그는 고치지 않는다.

## 규칙

| 대상 | 바꾸는 방법 |
|---|---|
| IP 주소(구분이 필요한 것) | 역할 별칭으로 바꾼다. 서버는 `API-1` · `API-2`, 클라이언트는 `교사단말A` · `교사단말B` 처럼 역할 + 등장 순서로 붙인다. |
| IP 주소(구분이 필요 없는 것) | 뒤 두 옥텟을 `x` 로 바꾼다(예: `10.20.x.x`). |
| 이메일 | `<이메일>` 로 바꾼다. 도메인도 남기지 않는다. |
| 학생 식별자(`STU-<숫자>`) | 등장 순서대로 `학생A` · `학생B` 로 바꾼다. URL · 쿼리 문자열 · 사유 문구 안의 것도 포함한다. |
| 토큰(Authorization 헤더 · 세션 ID · API 키 · JWT) | `<토큰>` 으로 바꾼다. 앞 몇 글자도 남기지 않는다. |
| 비밀번호 · 접속 문자열 | `<비밀번호>` 로 바꾼다. JDBC URL 은 계정 · 비밀번호 · 호스트를 가린다. |

## 적용 방법

- 별칭은 문서 안에서 일관되게 쓴다. 같은 값은 항상 같은 별칭이다.
- 별칭의 뜻은 역할로만 설명한다(예: "`API-1` = 요청을 처리한 앱 서버"). 원래 값과 별칭을 나란히 적지 않는다.
- 대응표(원래 값 ↔ 별칭)는 파일로 남기지 않는다. 마스킹 전 원본을 임시 폴더에 복사해 두지도 않는다.
- 민감한 값이 든 줄은 줄 전체를 옮기지 않고 필요한 부분만 발췌한다. 확인 방법에 적는 명령도 그 필드를 출력하지 않게 쓴다(`cut` · `grep -o` · `awk` 로 필요한 열만).
- 내부 ID(`classId` · `distributionId` 등) · 건수 · 커넥션 객체 ID · 스레드 이름은 가리지 않는다.

## 저장 전 점검

- 리포트에서 IP · 이메일 · `STU-` · `Bearer` · `password` 패턴을 검색해 0건인지 확인한다.
- 리포트 맨 끝에 적용 건수를 한 줄로 적는다: `마스킹 적용: IP 주소 N건(역할 별칭 n · x 치환 n) · 학생 식별자 N건 · 이메일 N건 · 토큰류 N건 · 비밀번호 · 접속 문자열 N건`
