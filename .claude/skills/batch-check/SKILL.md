# 배치 점검

일자별 배치 로그(`*.log`)와 적재 건수 CSV(`datamart-counts.csv`)를 점검한다.

## 입력
- 로그 폴더: `$ARGUMENTS`. 비어 있으면 `pipeline-samples/batch-logs`.
- CSV: 로그 폴더의 상위 폴더에 있는 `datamart-counts.csv`. 없으면 사용자에게 경로를 묻는다.
- 로그를 통째로 읽지 않는다. 먼저 한 파일의 `head` 로 형식을 보고, `grep` · `awk` · `wc` 로 필요한 줄만 뽑는다.

## 점검 기준
1. **실행 여부**: 다른 날 매일 돌던 job 이 그날 로그에 없거나, START 만 있고 종료(SUCCESS/FAIL) 기록이 없으면 이상.
2. **중복 실행**: 같은 날 같은 job 의 SUCCESS 가 2회 이상이면 이상.
3. **적재 건수**: 직전 7일 평균에서 30% 넘게 벗어나면 이상. 0건은 무조건 이상.
4. **지연**: 소요 시간이 그 job 의 평소 소요 시간의 2배를 넘으면 이상.

## 규칙
- **근거 표기**: 로그는 `파일:줄번호`, 건수는 `datamart-counts.csv:<행번호>`. 근거 없는 이상은 적지 않는다.
- **원인 추측 금지**: 로그에 없는 원인은 쓰지 않는다. 원인은 "확인 필요"로 남기고, 무엇을 더 봐야 하는지만 적는다.
- **계산은 명령으로**: 평균 · 편차 · 비율은 암산하지 않고 awk 등으로 계산한다. 임시 스크립트는 저장소 밖(스크래치패드)에 둔다.
- 계산 기준을 리포트에 적는다(예: 7일 평균에 쓴 일수, 지연의 비교 대상 평균).
- 점검 대상이 아닌 반복 WARN 은 "참고"로 따로 적고 이상 건수에 넣지 않는다.

## 리포트
먼저 날짜 · job · 점검 항목 · 근거 열의 표로 사용자에게 보여 준다. 저장은 사용자가 요청할 때만 한다.

저장 위치: `docs/batch-check/report.md` (한국어)
1. 맨 위 요약 한 줄: 점검 기간, 이상 건수
2. 이상 목록 표: 날짜 / job / 점검 항목 / 근거 / 영향 추정 / 다음 확인 사항
3. 참고(이상 기준 외 관찰)
4. 맨 아래 "이상 없음으로 판정한 날짜" 목록

- 영향 추정은 로그 · CSV 에 기록된 범위만 쓴다. 추정이면 "가능성"으로 표시한다.
- **이상이 한 건도 없으면 파일을 만들지 않고 "이상 없음" 한 줄만 답한다.**
