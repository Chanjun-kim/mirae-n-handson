# legacy/item-bank-php 비즈니스 규칙 후보

> 분석 범위: 문항 검색의 조건 조합 · 정렬 · 페이지, 문항 등록 검증 · 저장, 공개 · 제외 조건, 단원 목록.
> 근거는 `파일:줄번호` 형식이다. PHP 파일은 `legacy/item-bank-php/` 기준, 스키마는 `db/mariadb/init/` 기준이다.
> 진입점 · 의존 관계는 [ARCHITECTURE.md](ARCHITECTURE.md), 테이블 · 데이터 흐름은 [ERD.md](ERD.md) 를 본다.
> 이 문서는 코드를 읽어 뽑은 **후보**다. 실제 레거시를 실행해 확인하지 않았다.

**확신도 기준**
- 확실: 코드의 조건문 · SQL 로 확인했다.
- 추정: 이름이나 주석으로 짐작했다.

**수정 기능:** 이 모듈에는 문항 수정 화면이 없다. `UPDATE` 문도 없다(ERD.md §3). 그래서 "수정 시 검증" 규칙은 뽑을 것이 없다.
- 디렉터리 목록으로 확인했다. PHP 화면은 `index.php` · `search.php` · `register.php` · `units.php` 네 개이고, 그 밖에는 `inc/`(`db.php`, `layout.php`) · `vendor/` · `Dockerfile` 뿐이다.
- 메뉴에도 검색 · 등록 · 단원 목록만 있다(`index.php:9-11`).
- `UPDATE` 는 `register.php:87` 의 `FOR UPDATE`(행 잠금) 하나만 나오고, 이것은 수정 문이 아니다.

## 1. 공개 · 제외 조건

### BR-01 검색은 공개 문항만 대상으로 한다
- **규칙:** 문항의 `status` 가 `'A'` 가 아니면 검색 결과와 검색 건수에서 제외한다.
- **근거:** `search.php:522`, `01-schema.sql:70`
- **근거 코드:**
  ```php
  $from   = " FROM v_item_public";                 // search.php:522
  ```
  ```sql
  WHERE i.status = 'A';                           -- 01-schema.sql:70
  ```
- **확신도:** 확실
- **비고:**
  - `'A'` 는 매직 값이다.
  - `A=공개 D=삭제 R=검수중` 이라는 코드 값 의미는 주석만 있음(`01-schema.sql:26`).
  - 같은 조건이 BR-02 에도 따로 구현되어 있다.

### BR-02 단원 목록의 문항 수는 공개 문항만 센다
- **규칙:** 단원별 문항 수를 셀 때 `status` 가 `'A'` 가 아닌 문항은 세지 않는다.
- **근거:** `units.php:17`
- **근거 코드:**
  ```php
  (SELECT COUNT(*) FROM item i WHERE i.unit_id = u.id AND i.status = 'A') AS item_count
  ```
- **확신도:** 확실
- **비고:**
  - 같은 규칙이 두 곳에 구현되어 있다. BR-01 은 뷰를 쓰고, 이 규칙은 SQL 을 직접 쓴다.
  - 주석 "삭제 · 검수중 문항은 세지 않는다"(`units.php:15`)는 코드와 일치한다.
  - 문항이 0개인 단원도 목록에 나온다. `unit` 을 조건 없이 조회하고 문항 수는 상관 서브쿼리로 붙이기 때문이다(`units.php:16-19`).
    ```php
    $sql = "SELECT u.id, u.code, u.name, u.grade,
                   (SELECT COUNT(*) FROM item i WHERE i.unit_id = u.id AND i.status = 'A') AS item_count
              FROM unit u
             ORDER BY u.grade ASC, u.code ASC";
    ```

### BR-03 등록한 문항은 검수중 상태로 저장된다
- **규칙:** 문항을 등록하면 `status` 를 `'R'` 로 저장한다. 따라서 BR-01 · BR-02 에 따라 검색과 단원별 문항 수에 나오지 않는다.
- **근거:** `register.php:93-94`
- **근거 코드:**
  ```php
  "INSERT INTO item (id, unit_id, title, stem, level, status, created_at, updated_at)
   VALUES (?, ?, ?, ?, ?, 'R', NOW(), NOW())"
  ```
- **확신도:** 확실
- **비고:**
  - 주석 "검수 완료 전까지 검색 화면에 나오지 않는다"(`register.php:84`)와 안내 문구 "검수 완료 후 검색에 노출됩니다"(`register.php:116`)는 코드와 일치한다.
  - `'R'` → `'A'` 로 바꾸는 코드는 이 모듈에 없다(미확인).
  - 스키마의 `status` 기본값은 `'A'` 다(`01-schema.sql:26`). 등록 화면은 이 기본값을 쓰지 않고 `'R'` 을 명시한다.

## 2. 문항 검색 — 조건 조합

### BR-04 검색 조건은 모두 AND 로 결합한다
- **규칙:** 키워드 · 단원 · 난이도 · 태그 조건이 여러 개 주어지면 모두 만족하는 문항만 보여 준다.
- **근거:** `search.php:44`, `:98`, `:118`, `:215`, `:218`, `:226`, `:244`
- **근거 코드:**
  ```php
  $where    = " WHERE 1=1";                          // :44
  $where .= " AND unit_code = ?";                    // :118
  $where .= " AND level = ?";                        // :218
  ```
- **확신도:** 확실
- **비고:**
  - OR 로 결합하는 조건은 키워드 안에서만 나온다(BR-06).
  - 네 조건 모두 값을 `trim` 한 뒤 비어 있으면 조건을 붙이지 않는다(`search.php:85`, `:90`, `:109-110`, `:235-236`). 난이도만 예외로, 비어 있으면 `level < 5` 가 붙는다(`:211`, `:214-215`, BR-11).
    ```php
    $level = trim($level);                              // :211
    if ($level == '') {                                 // :214
        $where .= " AND level < 5";                     // :215
    $tag = trim($tag);                                  // :235
    if ($tag !== '') {                                  // :236
    ```
  - `page` 는 `trim` 하지 않는다(`search.php:337`).

### BR-05 파라미터가 배열이면 첫 값만 쓴다
- **규칙:** 검색 파라미터(`q`, `unit`, `level`, `tag`, `sort`, `dir`, `page`)가 배열로 들어오면 첫 번째 값만 쓴다.
- **근거:** `search.php:55`, `:59`, `:63`, `:67`, `:71`, `:75`, `:79`
- **근거 코드:**
  ```php
  $q = is_array($params['q']) ? (string)reset($params['q']) : (string)$params['q'];
  ```
- **확신도:** 확실
- **비고:** 없음

### BR-06 키워드는 제목 또는 지문에서 부분 일치로 찾는다
- **규칙:** 키워드가 비어 있지 않으면, 앞뒤 공백을 제거한 값이 제목 또는 지문에 포함된 문항을 찾는다.
- **근거:** `search.php:85`, `:90`, `:97-98`
- **근거 코드:**
  ```php
  $q = trim($q);                                      // :85
  $like = '%' . $q . '%';                             // :97
  $where .= " AND (title LIKE ? OR stem LIKE ?)";     // :98
  ```
- **확신도:** 확실
- **비고:**
  - `%` · `_` 를 이스케이프하지 않으므로 와일드카드로 동작한다(BR-08).
  - 대소문자 구분 여부는 컬레이션(`utf8mb4_unicode_ci`, `01-schema.sql:33`)에 따른다. 실행으로 확인하지 않았다.

### BR-07 키워드가 100자를 넘으면 100자까지만 쓴다
- **규칙:** 키워드가 100자를 넘으면 앞 100자로 자르고 경고를 보여 준다.
- **근거:** `search.php:86-88`, `:494`
- **근거 코드:**
  ```php
  if (mb_strlen($q, 'UTF-8') > 100) {
      $q = mb_substr($q, 0, 100, 'UTF-8');
  ```
- **확신도:** 확실
- **비고:** 매직 넘버 `100` 이 서버(`:86`, `:87`)와 폼 `maxlength="100"`(`:494`) 세 곳에 있다.

### BR-08 한 글자 키워드와 와일드카드 문자는 경고만 하고 그대로 검색한다
- **규칙:** 키워드가 한 글자이거나 `%` · `_` 를 포함하면 경고를 보여 주고, 검색은 그대로 한다.
- **근거:** `search.php:91-96`
- **근거 코드:**
  ```php
  if (mb_strlen($q, 'UTF-8') === 1) {
  if (strpos($q, '%') !== false || strpos($q, '_') !== false) {
      $warnings[] = '키워드의 % 와 _ 는 와일드카드로 처리됩니다.';
  ```
- **확신도:** 확실
- **비고:** 없음

### BR-09 단원은 단원 코드와 정확히 일치하는 문항만 찾는다
- **규칙:** 단원 값이 비어 있지 않으면, 앞뒤 공백을 제거한 값과 `unit_code` 가 같은 문항만 찾는다.
- **근거:** `search.php:109-110`, `:118`
- **근거 코드:**
  ```php
  $unit = trim($unit);                                // :109
  $where .= " AND unit_code = ?";                     // :118
  ```
- **확신도:** 확실
- **비고:**
  - 대소문자 구분 여부는 컬레이션(`utf8mb4_unicode_ci`)에 따른다. 실행으로 확인하지 않았다.
  - 폼의 선택 표시는 PHP 의 `===`(대소문자 구분)로 비교한다(`search.php:162`).

### BR-10 단원 코드 형식 · 대소문자 · 등록 여부가 틀려도 조회는 그대로 한다
- **규칙:** 단원 코드가 아래 중 하나에 해당하면 경고를 보여 주고, 조건은 입력값 그대로 적용한다.
  - 형식 `영문 1자 + 숫자 1~2자리 + '-' + 숫자 1~2자리` 가 아니다.
  - 소문자를 포함한다.
  - `unit` 테이블에 없는 코드다.
- **근거:** `search.php:111-117`, `:125`, `:141-142`
- **근거 코드:**
  ```php
  if (!preg_match('/^[A-Za-z][0-9]{1,2}-[0-9]{1,2}$/', $unit)) {   // :111
  if ($unit !== strtoupper($unit)) {                               // :115
      $warnings[] = '등록되지 않은 단원 코드입니다: ' . $unit;       // :142
  ```
- **확신도:** 확실
- **비고:**
  - 형식 정규식의 `{1,2}` 가 매직 넘버다.
  - 주석 "(결과는 대개 0건)"(`:112`)은 주석만 있음.

### BR-11 난이도가 비어 있으면 난이도 5 문항을 제외한다
- **규칙:** 난이도 값이 비어 있거나 파라미터가 없으면, 난이도가 5 미만(1~4)인 문항만 찾는다.
- **근거:** `search.php:211`, `:213-216`
- **근거 코드:**
  ```php
  // 난이도 값이 비어 있으면 전체 난이도 검색 (1~5 모두 포함)
  if ($level == '') {
      $where .= " AND level < 5";
  ```
- **확신도:** 확실
- **비고:**
  - **주석과 코드가 다르다.** 주석은 "1~5 모두 포함"이다(`:213`). 코드는 5를 뺀다. 이 문서는 코드 기준으로 썼다.
  - 폼의 "전체" 옵션(`:192`)을 고르거나 아무 조건 없이 검색해도 이 규칙이 적용된다.
  - 매직 넘버 `5` 가 있다.

### BR-12 난이도가 1~5 한 자리 숫자이면 그 난이도와 같은 문항만 찾는다
- **규칙:** 난이도 값이 정확히 `1`~`5` 중 하나이면 `level` 이 그 값과 같은 문항만 찾는다.
- **근거:** `search.php:217-220`
- **근거 코드:**
  ```php
  else if (preg_match('/^[1-5]$/', $level)) {
      $where .= " AND level = ?";
  ```
- **확신도:** 확실
- **비고:** 난이도 범위 `1~5` 가 BR-11, BR-26, `register.php:163`, 스키마 주석(`01-schema.sql:25`)에 각각 따로 있다.

### BR-13 난이도가 1~5 밖이면 경고하고 정수로 바꿔 비교한다
- **규칙:** 난이도 값이 비어 있지도 않고 `1`~`5` 도 아니면, 경고를 보여 주고 `(int)` 로 변환한 값과 같은 문항을 찾는다.
- **근거:** `search.php:223-229`
- **근거 코드:**
  ```php
  $warnings[] = '난이도는 1~5 사이여야 합니다.';
  $where .= " AND level = ?";
  $values[] = (int)$level;
  ```
- **확신도:** 확실
- **비고:**
  - PHP `(int)` 변환 규칙이 그대로 적용된다. `abc` 는 `0`, `2.7` 은 `2` 가 된다. 두 번째 경우 경고와 함께 난이도 2 문항이 나온다.
  - 주석 "(대개 0건)"(`:224`)은 주석만 있음.

### BR-14 태그는 태그 이름과 정확히 일치하는 문항만 찾는다
- **규칙:** 태그 값이 비어 있지 않으면, 앞뒤 공백을 제거한 값과 이름이 같은 태그가 붙은 문항만 찾는다.
- **근거:** `search.php:235-236`, `:244-245`
- **근거 코드:**
  ```php
  $where .= " AND EXISTS (SELECT 1 FROM item_tag it JOIN tag t ON t.id = it.tag_id"
          . " WHERE it.item_id = v_item_public.id AND t.name = ?)";
  ```
- **확신도:** 확실
- **비고:**
  - 태그는 한 번에 하나만 받는다(BR-05).
  - `LIKE` 가 아니므로 `%` · `_` 는 문자 그대로 비교한다. 경고만 한다(`:237-238`).

### BR-15 태그 이름이 50자를 넘으면 50자까지만 쓴다
- **규칙:** 태그 값이 50자를 넘으면 앞 50자로 자르고 경고를 보여 준다.
- **근거:** `search.php:240-242`
- **근거 코드:**
  ```php
  if (mb_strlen($tag, 'UTF-8') > 50) {
      $tag = mb_substr($tag, 0, 50, 'UTF-8');
  ```
- **확신도:** 확실
- **비고:** 매직 넘버 `50` 은 `tag.name VARCHAR(50)`(`01-schema.sql:37`)과 같은 값이다.

### BR-16 등록되지 않은 태그여도 조회는 그대로 한다
- **규칙:** 태그 값이 `tag` 테이블의 이름 목록에 없으면 경고를 보여 주고, 조건은 그대로 적용한다.
- **근거:** `search.php:251-260`
- **근거 코드:**
  ```php
  if ($opt['value'] !== '' && $opt['value'] === $tag) {
  ...
  $warnings[] = '등록되지 않은 태그입니다: ' . $tag;
  ```
- **확신도:** 확실
- **비고:**
  - 등록 여부는 PHP `===`(대소문자 구분)로 비교한다. 반면 SQL 조건(BR-14)은 컬레이션을 따른다.
  - 주석 "(없어도 조회는 그대로 한다 → 0건)"(`:250`) 중 "0건" 부분은 주석만 있음.

## 3. 문항 검색 — 정렬

### BR-17 정렬 기준이 없으면 난이도 내림차순, 같으면 ID 오름차순으로 정렬한다
- **규칙:** `sort` 가 비어 있거나 알 수 없는 값이면 `level DESC, id ASC` 로 정렬한다. 알 수 없는 값일 때는 경고를 보여 준다.
- **근거:** `search.php:317-326`
- **근거 코드:**
  ```php
  case '':
      // 기본 정렬: 어려운 문항부터, 같은 난이도면 번호 순
      $orderBy = " ORDER BY level DESC, id ASC";
  ```
- **확신도:** 확실
- **비고:**
  - 주석과 코드는 일치한다.
  - BR-11 과 겹쳐서, 조건 없이 검색하면 첫 화면은 난이도 4 문항부터 나온다.
  - 같은 `ORDER BY` 문자열이 `:305`, `:319`, `:325` 세 곳에 있다.

### BR-18 정렬 기준별 정렬 방식
- **규칙:** `sort` 값에 따라 아래와 같이 정렬한다. `sort` · `dir` 는 소문자로 바꾸고 앞뒤 공백을 제거한 뒤 비교한다.

  | `sort` | `dir` 가 없거나 잘못됐을 때 | 결과 |
  |---|---|---|
  | `id` | 오름차순 | `id` |
  | `title` | 오름차순 | `title`, 같으면 `id ASC` |
  | `unit` | 오름차순 | `unit_code`, 같으면 `level DESC`, 같으면 `id ASC` |
  | `level` | 내림차순 | `level`, 같으면 `id ASC` |
  | `created` | 내림차순 | `created_at`, 같으면 `id ASC` |

- **근거:** `search.php:266-273`, `:276-315`
- **근거 코드:**
  ```php
  $orderBy = " ORDER BY unit_code ASC, level DESC, id ASC";      // :297
  if ($dir === 'asc') {                                          // :302 (level)
  ```
- **확신도:** 확실
- **비고:**
  - `unit` 정렬은 `dir` 와 관계없이 보조 정렬이 항상 `level DESC` 다(`:295`, `:297`).
  - `dir` 가 `asc` · `desc` 가 아니면 경고를 보여 주고 없는 것으로 친다(`:268-272`).
  - `created` 는 정렬 기준으로 받지만 열 머리글 링크는 없다(`:392-397`).
  - 기본 방향은 화면 표시용 값에도 같은 규칙으로 들어간다(`:328-331`).

### BR-19 난이도 열 머리글은 첫 클릭에 내림차순으로 정렬한다
- **규칙:** 현재 정렬 기준이 아닌 열 머리글을 누르면 오름차순으로 정렬한다. 난이도 열만 내림차순으로 정렬한다. 현재 정렬 기준 열을 다시 누르면 방향을 뒤집는다.
- **근거:** `search.php:400-413`
- **근거 코드:**
  ```php
  } else if ($key === 'level') {
      // 난이도는 첫 클릭에 내림차순
      $nextDir = 'desc';
  ```
- **확신도:** 확실
- **비고:** 없음

## 4. 문항 검색 — 페이지

### BR-20 한 페이지에 20건을 보여 준다
- **규칙:** 검색 결과는 한 페이지에 20건씩 보여 주고, `(page - 1) × 20` 건을 건너뛴다.
- **근거:** `search.php:349`, `:523`, `:553`
- **근거 코드:**
  ```php
  $offset = ($page - 1) * 20;                         // :349
  $limit  = " LIMIT 20 OFFSET " . (int)$offset;       // :523
  'page_size'    => 20,                               // :553
  ```
- **확신도:** 확실
- **비고:** 매직 넘버 `20` 이 세 곳에 따로 있다. 페이지 수 계산(`search.php:685`)은 `:553` 값을 쓴다.

### BR-21 페이지 번호는 1~999 로 제한한다
- **규칙:** 페이지 번호가 숫자가 아니거나 1보다 작으면 1페이지로 본다. 999보다 크면 999페이지로 보고 경고를 보여 준다.
- **근거:** `search.php:336-348`
- **근거 코드:**
  ```php
  if (preg_match('/^[0-9]+$/', $pageRaw)) {
  if ($page > 999) {
      $page = 999;
  ```
- **확신도:** 확실
- **비고:**
  - 매직 넘버 `999` 가 있다.
  - 숫자가 아닐 때의 경고는 값이 `''` · `'1'` 이 아닐 때만 보여 준다(`:339-340`).
  - 전체 페이지 수보다 큰 번호는 제한하지 않는다. 이때 건수는 표시되고 표는 비어 있다(`search.php:657`, `:672`).

### BR-22 검색 결과가 0건이면 안내 문구만 보여 준다
- **규칙:** 총 건수가 0이면 결과 표 대신 "검색 결과가 없습니다" 를 보여 준다.
- **근거:** `search.php:657-660`
- **근거 코드:**
  ```php
  if ($total === 0) {
      echo '<p id="message">검색 결과가 없습니다</p>' . "\n";
  ```
- **확신도:** 확실
- **비고:** 페이지 링크는 전체 페이지 수가 2 이상일 때만, 1부터 마지막 페이지까지 모두 출력한다(`search.php:686`, `:692`).

## 5. 문항 등록 — 검증

검증에 하나라도 걸리면 저장하지 않고 오류 목록을 보여 준다(`register.php:83`, `:133-139`).

### BR-23 제목은 앞뒤 공백을 뺀 길이가 5~200자여야 한다
- **규칙:** 앞뒤 공백을 제거한 제목이 5자 미만이거나 200자를 넘으면 등록하지 않는다.
- **근거:** `register.php:41`, `:49-54`
- **근거 코드:**
  ```php
  if (mb_strlen($title, 'UTF-8') < 5) {
  if (mb_strlen($title, 'UTF-8') > 200) {
  ```
- **확신도:** 확실
- **비고:**
  - 가운데 공백은 길이에 포함된다. 주석 "공백 제외 아님, 앞뒤 공백만 제거"(`:48`)와 일치한다.
  - 매직 넘버 `5`, `200` 이 있다. `200` 은 `item.title VARCHAR(200)`(`01-schema.sql:23`)과 같은 값이다.
  - 폼 라벨 "제목 (5자 이상)"(`:143`)에는 상한이 없다.

### BR-24 지문은 앞뒤 공백을 뺀 값이 비어 있으면 안 된다
- **규칙:** 앞뒤 공백을 제거한 지문이 빈 문자열이면 등록하지 않는다.
- **근거:** `register.php:42`, `:56-58`
- **근거 코드:**
  ```php
  if ($stem === '') {
      $errors[] = '지문을 입력해야 합니다.';
  ```
- **확신도:** 확실
- **비고:** 지문 길이 상한 검사는 없다(`item.stem` 은 `TEXT`, `01-schema.sql:24`).

### BR-25 단원은 `unit` 테이블에 있는 id 여야 한다
- **규칙:** 선택한 단원 id 가 `unit` 테이블의 id 목록에 없으면 등록하지 않는다.
- **근거:** `register.php:27`, `:60-68`
- **근거 코드:**
  ```php
  if ((string)$u['id'] === $unitId) {
      $unitOk = true;
  ```
- **확신도:** 확실
- **비고:**
  - 검색은 단원을 `code` 로 받는다(BR-09). 등록은 `id` 로 받는다.
  - 없는 단원이어도 검색은 조회를 계속하지만(BR-10), 등록은 막는다.

### BR-26 난이도는 1~5 한 자리 숫자여야 한다
- **규칙:** 난이도 값이 정확히 `1`~`5` 중 하나가 아니면 등록하지 않는다.
- **근거:** `register.php:70-72`
- **근거 코드:**
  ```php
  if (!preg_match('/^[1-5]$/', $level)) {
      $errors[] = '난이도는 1~5 사이여야 합니다.';
  ```
- **확신도:** 확실
- **비고:**
  - 검색(BR-12)과 정규식이 같다.
  - 빈 값(파라미터 없음 포함)도 정규식에 맞지 않으므로 거부한다. 값은 먼저 `trim` 한다(`register.php:44`).
    ```php
    $level  = isset($_POST['level'])  ? trim((string)$_POST['level'])  : '';
    ```
    검색은 빈 난이도를 `level < 5` 조건으로 처리한다(BR-11).
  - 1~5 밖의 값이면 검색은 경고만 하고 조회를 계속하지만(BR-13), 등록은 막는다.

### BR-27 목록에 없는 태그는 오류 없이 버린다
- **규칙:** 선택한 태그 id 중 `tag` 테이블에 없는 것은 오류를 내지 않고 저장 대상에서 뺀다.
- **근거:** `register.php:74-81`
- **근거 코드:**
  ```php
  if ((string)$t['id'] === (string)$tid) {
      $validTagIds[] = (int)$tid;
  ```
- **확신도:** 확실
- **비고:**
  - 주석 "태그는 목록에 있는 것만"(`:73`)은 코드와 일치한다.
  - 태그는 필수가 아니다. 0개여도 등록된다(`:104`).
  - 같은 태그 id 가 두 번 들어오면 중복을 제거하지 않는다. 그러면 `item_tag` PK(`01-schema.sql:45`)가 충돌해 BR-29 의 롤백으로 이어진다. 코드와 스키마를 읽고 내린 결론이며, 실행으로 확인하지 않았다.

| CX-09 (검색 값 trim 후 빈 값이면 조건 없음) | 키워드 · 단원 · 난이도 · 태그는 확인. `page` 는 trim 하지 않는다(`search.php:337`) | BR-04 비고에 추가 |
