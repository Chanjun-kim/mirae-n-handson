# RCA — b-deploy-5xx

> **작성 범위: 1 ~ 3절(가설 표)까지.** 로그 반증 · 코드 대조 · 판정과 4절 이후(원인 · 근거 · 수정안 · 재발 방지 · 모니터링 · 확인하지 못한 것)는 아직 쓰지 않았다. 이 문서에는 원인 판정이 없다.

## 1. 수집 범위

대상: `incident-logs/b-deploy-5xx/` 의 파일 3개. 이 절은 "어느 시간대를 볼 것인가"만 정한다. 원인 판단은 포함하지 않는다.

조사 방법: 로그 2개는 통째로 읽지 않고 `wc` · `head` · `tail` · `grep -c` · `grep -n` · `sed -n` · `awk` 집계로만 확인했다. `deploy-history.md`(39줄)만 전체를 읽었다.

## 2. 타임라인

대상: 1.7 의 수집 구간. 시각은 모두 KST 다. 로그와 배포 이력에 있는 사건만 적었고 원인 해석은 포함하지 않는다.

읽는 법:

- 형식: 시각 | 출처(파일:줄번호) | 사건 요약 | 원문 발췌(80자 이내, `…` 는 생략).
- 출처 약칭: `app` = `app.log`, `access` = `nginx-access.log`, `deploy` = `deploy-history.md`.
- 반복되는 메시지는 첫 발생 줄에 "이후 N건"으로 묶었다. 분 단위 건수는 1.5 표에 있다.
- **(선후 불확실)**: 서로 다른 파일의 시각이 같은 초 안이라 순서를 단정할 수 없는 곳. `app` 은 밀리초, `access` · `deploy` 는 초 단위다.
- 마스킹: 학생 식별자는 등장 순서대로 `학생A` 식 별칭으로 바꿨다. IP 는 역할 별칭(`API-1` = 배포 대상 호스트, `API-2` = 대기 호스트, `교사단말A` = 500 응답을 받은 클라이언트)으로 바꿨다. 배포자 · 승인자는 이메일 대신 역할로 적었다.

## 3. 가설과 검증

500 46건 · 502 8건 · `unhandled exception` ERROR 46건은 **증상**이다. 이 절은 그 증상을 만들었을 수 있는 상류 조건을 계층별로 가설로 세우고, 각 가설을 무엇으로 틀렸다고 할 수 있는지만 적는다. **어느 가설이 맞는지는 판정하지 않는다.** 확인 방법의 명령은 판정을 위해 따로 실행하지 않았고(일부 값은 1 · 2절의 집계에 이미 나와 있다), 저장소의 코드 · 설정 · 스키마도 열어 보지 않았다.

읽는 법:

- 지지 근거의 `b-deploy-5xx.md §<절>` 은 이 문서의 절이고, 괄호 안은 원본 줄이다.
- 로그 명령은 `incident-logs/b-deploy-5xx/` 에서, 코드 경로는 저장소 루트 기준이다. 코드 경로는 `deploy-history.md` 와 스택 트레이스에 적힌 이름이다.
- 가설들은 서로 배타적이지 않다. 둘 이상이 함께 성립할 수 있다.
- 운영 DB · 게이트웨이에서만 확인할 수 있는 값은 명령을 만들지 않고 "담당자에게 요청"으로 적었다.

### 3.6 가설을 가르는 기준

- **스택 경로가 배포 전후로 다르다.** 예외 문구는 46건이 같지만 배포 전 7건은 `loadOrThrow`(배포 41 을 직접 읽음), 배포 후 39건은 `listByClass`(학급의 배포 목록을 읽음)에서 났다. 배포 후 경로가 v1.4.2 에서 새로 생긴 것인지가 H1 을, 두 경로가 같은 행 때문에 실패하는지가 H2 를 가른다.
- **배포 41 이 학급 1 인가.** 맞으면 H1 과 H2 는 "배포 전부터 있던 데이터(H2)를 새 경로(H1)가 읽게 됐다"로 이어진다. 아니면 학급 1 에 과제 9 를 가리키는 다른 행이 있거나 H2 의 범위가 다르다. 로그만으로는 정할 수 없다.
- **`redistributed` INFO 가 커밋 전인가 후인가.** 후라면 H3 의 "재시도마다 재배포가 한 번 더 실행됐다"가 성립하고 데이터 영향(학급 1 배포 42 · 43 의 중복 재배포 39건)이 생긴다. 전이라면 500 은 응답 오류에 그친다.
- **H4 는 범위가 다르다.** H1 ~ H3 은 500 46건, H4 는 502 8건에 대한 가설이다. H4 가 맞아도 500 의 설명은 되지 않는다.

### 3.7 가설로 세우지 않은 계층

- **DB 성능 · 커넥션 풀**: 풀 타임아웃 · SQL 오류 줄이 0건이고(§2.5) 이 묶음에 DB 로그가 없다. 예외는 46건 모두 "엔티티 없음"이며 시간 초과가 아니다.
